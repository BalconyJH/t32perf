# Development Plan Conformance Matrix

This document maps the original development plan's P0–P8, quality strategy, and Definition of Done to repository implementation and evidence. It does not treat synthetic data, mocks, CI configuration, or the harness itself as real TRACE32/MCU acceptance results.

Status definitions:

- `IMPLEMENTED`: Software implementation and automated tests both exist in the repository.
- `SOFTWARE_ONLY`: The complete software path exists, but evidence is only synthetic, golden, mock, or host-compiler evidence.
- `IN_PROGRESS`: A contract or local component exists, but the production end-to-end path is not closed.
- `EXTERNAL_EVIDENCE_REQUIRED`: The conclusion depends on a specified TRACE32 build, probe, board, firmware, RTOS, external platform, or official-tool run; the repository cannot fabricate it.
- `NOT_CLAIMED`: The plan explicitly leaves this for later; the current release makes no support claim.

## Health and security gates

The analysis-stage, analysis-summary, hotspots, compare, and Perfetto pipelines jointly enforce the quantitative-output boundary for `VALID`, `DEGRADED`, and `INVALID`. A non-`VALID` Session cannot produce trustworthy hotspots or a regression verdict; `DEGRADED` permits diagnostic display only, and `INVALID` retains diagnostic data only.

Artifact root, Session ID, portable paths, no-follow file access, per-file/Session/control-document quotas, SHA-256, create-new/atomic publish, catalog/manifest provenance chain, maintenance lease, and Controller single-flight are constrained by implementation and tests. Maintenance retention moves only complete Sessions; abandon moves an incomplete Session's entire directory, including staging/orphan/intent, to a separate quarantine using the exact inventory. Neither operation permanently deletes data or rewrites a Session in place.

Canonical Session/model families currently remain primarily `/v1`; Controller request/response additionally has the explicit `/v2` multi-output family. It is selected by the target-adapter protocol selector, not by a transparent upgrade of a v1 document; there is no capture-kind-based automatic migration. An empty migration route in the schema inventory only means that no migratable old Session major currently exists. Once a real old Session major exists, an explicit migration edge must be registered, a new Session and migration receipt created, and input provenance retained; in-place no-op migration is prohibited.

The repository software implementation now covers the main Host, contract, analysis, artifact, and production-control scope; the TC234L SNOOPer V1 candidate's adapter/control/parser/qualification/driver software chain is also present. Windows official `trace_processor` synthetic import and the 2026-08-25 real t32mcp binary preflight are archived, but the preflight binds historical adapter digest `feb461...` and does not cover the current runtime bundle. This does not mean that a production V2 profile or real TASKEVENTS adapter exists. RTOS/Linux/the second platform, the real TASKEVENTS/custom-event adapter, vendor fixture/mapping, native differential, and cross-platform/UI Perfetto evidence all await external acceptance; synthetic fixtures, preflight, the HIL harness, and workflow configuration cannot fill those evidence gaps.
