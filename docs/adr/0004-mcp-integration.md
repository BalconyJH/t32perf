# ADR 0004: Keep the `t32mcp` Core Unchanged

Status: Accepted

## Decision

The first release integrates `t32mcp` through `skill-trace32-perf` and fixed-name CMM scripts. AREA returns only bounded framed JSON status, the Session ID, the manifest path, and artifact digests; trace data is written to a CLI-created staging directory.

External capture is not trusted merely because it originates from `t32mcp`. The host first registers a strict `t32perf.capture-config/v1`, then uses an explicit `t32perf.normalize-config/v1` to produce canonical observations, and finally verifies a capture attestation bound to the Session/request/observation/configuration digests with deployment Ed25519 policy. Only a receipt produced after host verification may enter analysis.

Lauterbach `t32mcp` v0.2.2 has only the three generic tools execute, collect, and abort, and globally permits only one PRACTICE script. T32Perf includes a production deployment driver. It reads strict `t32perf.t32mcp-driver-config/v1` from the fixed `<artifact-root>/.t32perf-control/deployment/t32mcp-driver.json` path; verifies the executable SHA-256, exact `t32mcp v0.2.2`, and every member of the runtime-only adapter manifest; and requires the configuration, canonical manifest bundle, installed profile, and compiled candidate to have the same implementation digest. Skill documentation and agent metadata are excluded from the runtime digest. The driver then launches a managed child over stdio and requires `tools/list` to contain exactly `execute_practice_skill`, `collect_practice_skill_response`, and `abort_practice_skill`; hidden `execute_practice`, or any extra or missing tool, is rejected.

The seven originally planned exact names are implemented by the T32Perf host façade, not presented as new upstream top-level MCP tools: `perf_capabilities`, `perf_capture`, `perf_get_status`, `perf_get_summary`, `perf_list_artifacts`, `perf_convert`, and `perf_compare`. The same typed façade now also includes `perf_run`, a closed provision-to-report orchestration. These operations return a closed, typed `t32perf.perf-surface/v1` payload; the driver executes only the exact next action in an immutable transaction. The high-level `controller drive` drives the façade, `controller drive-transaction` drives an existing transaction, `controller abort-upstream` performs the trusted two-phase abort, and `controller driver-preflight` checks only version, initialization, tool inventory, and shutdown.

The host provides `controller prepare/accept/abort/confirm-abort/status`. Requests, validated responses, abort plans, and abort receipts are immutable artifacts bound to the Session ID, Session operation, immutable Session request SHA-256, transaction ID, nonce, and exact controller-request artifact digest. One artifact root maps to one single-tenant t32mcp endpoint. A root namespace lock, a durable scan of all Sessions, and the `<artifact-root>/.t32perf-control/controller/trace32-driver-execution.lock` OS lease ensure that at most one external driver, low-level controller mutation, or public performance mutation is active. The lease covers version/init, tools, hooks, replacement, and cleanup.

The capture phase has no mutable cache; it reconstructs the unique phase from these artifacts and seven classes of operation-specific evidence. The host enforces `capabilities → configure → start → stop → health → export → cleanup`. Only accepted start/stop evidence changes the Session lifecycle; completed phases cannot create a new transaction, and `accept` for the original transaction may resume idempotently. Target-control `OK` is accepted only after the corresponding `t32perf.controller-*-evidence/v1` passes strict JSON, operation, binding, and semantic validation.

MCP transport limits each raw JSON line to 1 MiB, the official tool's sole text block and Controller wrapper to 64 KiB, and the framed JSON payload to 4 KiB. A pending wrapper may carry partial content, but its `<NOT FINISHED>` and `<CONTENT>` headers must each occur once and in the fixed order. Every other bounded response, including a malformed wrapper, is first written to the transaction's fixed host staging path, then passed to host `accept` to produce authoritative acceptance or rejection evidence.

The driver uses an append-only `t32perf.controller-driver-event/v1` journal for `dispatch_intent`, `fault_intent`, `fault_triggered`, `abort_attempt`, `abort_success_observed`, `workload_intent`, and `workload_complete`. Each event binds the immutable request/binding and, when applicable, the abort plan. The journal prevents a restart from repeating execute, collect, workload, a fault hook, or END. Ambiguous state fails closed, and an incomplete workload intent is never rerun. Workload and `trace32_disconnect_at_stop` are deployment-owned direct-argv hooks. Each hook binds its own executable SHA-256, bypasses the shell, uses a closed placeholder set, requires empty stdout, and has independent stderr, command-timeout, and driver-total-deadline limits; failure or timeout terminates the complete process tree. On Unix, success also waits for the dedicated hook process group to become empty, and trusted hooks may not move descendants into another session or process group. `driver_disconnect_at_export` executes Export first; the final staged response lets the host determine whether the fault was missed. Only strict pending first writes `fault_intent` and the bound abort plan, then uses the exact child handle to force a disconnect. On force success it writes `fault_triggered` and launches exactly one replacement child, after the same complete reload/reverification, to invoke official abort. After abort success is observed, only host confirmation is retried; END is not invoked again. A later shutdown failure does not revoke observed abort success. Cleanup failure is returned explicitly and durable quarantine remains.

## Security Boundaries

- `skill_name` and `script_name` are fixed constants in code and cannot accept a user path.
- Driver configuration may exist only at the fixed root control path. The t32mcp, workload, and TRACE32-disconnect executables must be absolute plain files and match their SHA-256 before every load or execution. The skill root, manifest members, and profile must be plain, link/reparse-free, and remain inside the verified package root.
- T32Perf owns Session isolation, path normalization, hashing, quotas, and overwrite prohibition.
- TRACE32 output and target-control evidence may be written only to a Controller-owned staging reservation; AREA returns only a bounded, binding-bound frame.
- Abort is a two-phase transaction: an abort plan does not release the slot. Once the deployment driver observes official upstream unit success, it immediately writes an unbound single-tenant abort receipt and terminalizes the Session. The manual low-level path still requires explicit confirmation from a trusted caller.
- A pending transaction blocks ingest, normalize, attest, analyze, and convert for its owner Session.
- The execution lease is not released after accepted Cleanup if the host has not yet materialized the authoritative capture-config.
- An external adapter key may declare only policy-fixed provider, adapter, mode, target, TRACE32, clock, core, and capability ceiling values.
- `perf_cleanup.cmm` resets capture state only and never deletes Session files.
- `controller driver-preflight` does not call a practice tool. Upstream creates RCL only in the tool handler, so this check does not connect TRACE32 and is not evidence of an endpoint, probe, or board run.
- If future work needs concurrent endpoints, transaction-bound abort acknowledgment, or named MCP tools, introduce a separate service and write a new ADR rather than piercing the upstream core.
